# Запуск «Стража» через Docker

Нужен только Docker Desktop (Windows, macOS) или Docker Engine (Linux). Python, Ollama и `uv` на компьютере ставить не нужно.

В образ **не входят** папка `отчет по проделанной работе`, `.venv` и локальные базы. Сборка копирует код `src`, страницы `static` и `entrypoint.py`. Прямые пакеты берутся из `requirements.txt` с `==`. Вместе с ними ставятся `uv==0.13.0` и `atomno-mcp-cbr-rates==0.1.11`.

## Быстрый запуск из этого репозитория

В корне проекта:

```bash
docker compose up --build
```

Первый раз скачает образы и модель `qwen2.5:3b` (около 2 ГБ). Дальше открывается сразу.

- Страж: http://127.0.0.1:38480
- Почта: http://127.0.0.1:38490

Порты на хосте нестандартные: `38480` (Страж) и `38490` (почта), оба слушают все интерфейсы — так одногруппники в той же Wi‑Fi сети открывают стенд по IP вашей машины. Внутри контейнера процессы по-прежнему на `8080` и `8090`; `STRAZH_MAIL_URL` остаётся `http://127.0.0.1:8090` (веб пишет в почту внутри контейнера). Ссылки «Почта» / «Страж» на страницах подставляют тот же hostname, с которого открыли сайт.

Секрет почты контейнер записывает в том `strazh-data`, файл `mail_secret`. Ключ файлов `strazh.db` и `mail.db` — рядом, файл `db_secret`, отдельно от почты и от торгового JWT. Оба файла базы закрыты этим ключом, права `0600`. В репозиторий и в переменные compose эти секреты не кладутся. Ящик создаёт регистрация на странице почты. Учётка Стража — отдельно, на ту же почту; пароль Стража может быть другим. Готового демо-входа нет. Страницы `/docs`, `/redoc` и `/openapi.json` на обоих портах выключены. Чтобы открыть схему локально, перед запуском задают `STRAZH_OPENAPI=1`. Обычный compose этого не делает.

Остановка: `Ctrl+C`, затем при необходимости `docker compose down`. Счета и письма остаются в томе `strazh-data`.

Локальный `start_mode_a.ps1` в корне репозитория по-прежнему работает без Docker на портах `8080` и `8090`.

## Показ одногруппникам в одной Wi‑Fi сети

1. Поднимите стек: `docker compose up -d --build`
2. Узнайте IP Wi‑Fi: `hostname -I` или настройки сети (пример: `10.82.34.44`).
3. Отдайте ссылки:
   - Страж: `http://<ваш-IP>:38480`
   - Почта: `http://<ваш-IP>:38490`
4. У одногруппника: сначала регистрация ящика на почте → потом регистрация в Страже на ту же почту (пароли могут различаться).
5. Свой MCP: в контейнере по умолчанию поднимаются учебные MCP на `127.0.0.1:9100–9103/mcp` (stub + 3 легенды). В «Мои MCP» список подсказок уже есть. Отключить автозапуск: `STRAZH_MCP_STUB=0`. Чужой localhost (не эти порты) по-прежнему запрещён (анти-SSRF). См. `examples/evil_mcp/README.md`.

Если страница не открывается с другого телефона/ноутбука — проверьте firewall хоста (`ufw` / «Брандмауэр») и что вы в одной сети `WiFi_CIT`, а не в гостевой изоляции клиентов.

## Скачать готовый стек с Docker Hub

После того как образ Стража выложен:

```bash
docker compose pull
docker compose up
```

По умолчанию берётся `rinakt/strazh:latest`. Другой тег: `STRAZH_IMAGE=другой/образ:latest`.

Официальный `ollama/ollama` тоже берётся с Docker Hub. Модель качается при первом старте и остаётся в томе `ollama`.

## Как выложить образ на Docker Hub

1. Войдите: `docker login`
2. Соберите и отправьте:

```bash
docker compose build
docker tag rinakt/strazh:latest rinakt/strazh:latest
docker push rinakt/strazh:latest
```

Если собирали локальный тег `strazh-stand:latest`:

```bash
docker tag strazh-stand:latest rinakt/strazh:latest
docker push rinakt/strazh:latest
```

Другому человеку достаточно `docker-compose.yml` и `docker compose up`.

## Что слушает контейнер

| Порт на хосте | Внутри контейнера | Сервис |
|---|---|---|
| 38480 | 8080 | Страж (чат, вход, заявки) |
| 38490 | 8090 | Почта |

Оба порта на хосте слушают все интерфейсы (`0.0.0.0`). Ollama внутри сети compose не публикуется наружу. Исходящий HTTPS к MOEX и ЦБ должен быть разрешён.
