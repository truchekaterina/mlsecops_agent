# Запуск «Стража» через Docker

Нужен только Docker Desktop (Windows, macOS) или Docker Engine + Compose (Linux). Python, Ollama и `uv` на компьютере **не** ставят.

В одном стеке: Ollama, модель `qwen2.5:3b`, Страж, почта, учебные MCP `:9100–9103`.

## Две команды

Из корня репозитория:

```bash
chmod +x start-docker.sh   # один раз
./start-docker.sh
```

Windows PowerShell:

```powershell
.\start-docker.ps1
```

То же без скрипта:

```bash
docker compose up -d --build
```

Скрипт сам ждёт `/api/health`. У `docker compose --wait` таймаут 60 с — для первой загрузки модели этого мало, поэтому в скрипте его нет.

Первый раз скачает образы и модель (~2 ГБ). Когда health Стража зелёный, скрипт печатает ссылки для себя (`127.0.0.1`) и для одногруппников (текущий IPv4 Wi‑Fi). Порты всегда `38480` и `38490`. IP Wi‑Fi выдаёт DHCP этой сети — его нельзя «зашить» в Docker: на другой точке он другой.

Если стек уже поднят, только ссылки:

```bash
./start-docker.sh urls
```

Дальше: **сначала ящик на почте**, потом регистрация в Страже на ту же почту. В чате приветствие получает короткий ответ модели без записи в книгу. «Сколько стоит Сбер» и «какие акции» показывают цену с Мосбиржи, не «около». «Купи 1 акцию Газпрома» уходит в агента: кнопку даёт его тул, баланс не меняется до кнопки. «Сделай на счёте 15000» книгу не меняет. MCP — [docs/КАК_РАБОТАТЬ_С_MCP.md](docs/КАК_РАБОТАТЬ_С_MCP.md).

Остановка: `docker compose down`. Счета, письма и модель остаются в томах `strazh-data` и `ollama`.

Логи: `docker compose logs -f`

## Что поднимается

| Сервис | Роль |
|--------|------|
| `ollama` | Модель внутри сети compose, наружу не публикуется |
| `ollama-pull` | Один раз качает `qwen2.5:3b`, затем завершается |
| `strazh` | Веб `:8080`, почта `:8090`, stub+легенды MCP `9100–9103` (entrypoint) |

Образ собирается из этого репозитория, тег `strazh:local` (не обязательно тянуть Docker Hub). Готовый чужой образ: `STRAZH_IMAGE=rinakt/strazh:latest docker compose up -d`.

Порты на хосте: `38480` (Страж) и `38490` (почта), все интерфейсы. Внутри контейнера `8080`/`8090`; `STRAZH_MAIL_URL=http://127.0.0.1:8090`.

Секреты почты, JWT и ключ баз контейнер пишет в том `strazh-data` (`mail_secret`, `jwt_secret`, `db_secret`). В репозиторий и в compose их нет. Готового демо-входа нет. `/docs` выключены, пока не задан `STRAZH_OPENAPI=1`.

Локальный `start_mode_a.ps1` без Docker — порты `8080` и `8090`.

## Показ одногруппникам в одной Wi‑Fi сети

Порты на хосте всегда одни: `38480` (Страж) и `38490` (почта). Адрес Wi‑Fi меняет роутер. Скрипт запуска сам подставляет текущий IPv4 — смотрите вывод `./start-docker.sh` или `./start-docker.sh urls`, не `hostname -I`.

1. `./start-docker.sh`
2. Скопируйте из вывода строки «Одногруппникам…»
3. У одногруппника: та же Wi‑Fi → ящик на почте → учётка Стража на ту же почту
4. MCP: в «Мои MCP» учебные URL `http://127.0.0.1:9100–9103/mcp` — это localhost **контейнера**, его видит процесс Стража. Свой MCP на этой же машине: `http://host.docker.internal:ПОРТ/mcp` (`extra_hosts: host-gateway` у сервиса `strazh`). Сервер слушает `0.0.0.0`. С чужого ноутбука в ту же Wi‑Fi — IP этого ноутбука, не `127.0.0.1`. Порты 9100–9103 с хоста не открыты и для учебных легенд не нужны.

Если страница не открывается с телефона — firewall хоста и одна сеть, не гостевая изоляция клиентов.

## Скачать готовый стек с Docker Hub

Если образ Стража уже выложен:

```bash
STRAZH_IMAGE=rinakt/strazh:latest docker compose pull
STRAZH_IMAGE=rinakt/strazh:latest docker compose up -d
```

Официальный `ollama/ollama` тоже с Docker Hub. Модель остаётся в томе `ollama`.

## Как выложить образ на Docker Hub

```bash
docker login
docker compose build
docker tag strazh:local rinakt/strazh:latest
docker push rinakt/strazh:latest
```

Другому человеку с тем же `docker-compose.yml`: `STRAZH_IMAGE=rinakt/strazh:latest docker compose up -d` (Ollama всё равно качает модель).

## Что слушает контейнер

| Порт на хосте | Внутри контейнера | Сервис |
|---|---|---|
| 38480 | 8080 | Страж (чат, вход, заявки, «Мои MCP») |
| 38490 | 8090 | Почта |
| — | 9100–9103 | Учебные MCP (только внутри контейнера) |

Ollama наружу не публикуется. Исходящий HTTPS к MOEX и ЦБ должен быть разрешён. Свой MCP на хосте контейнер достаёт по имени `host.docker.internal` (шлюз Docker), не по `127.0.0.1`.

Отключить учебные MCP: в environment Стража `STRAZH_MCP_STUB=0`.
